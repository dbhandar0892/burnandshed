- Premium trial/status is stored per account in the backend (entitlements table, start_trial RPC) and cached locally; why: signed-in users must keep Premium across devices and sign-ins.
- Premium features require an active sign-in; the account entitlement stays cached on the device after sign-out so returning members are recognized on sign-in; why: user wants signed-out users prompted to sign in.
- After gated-feature sign-in, return to the originating feature, including Premium plan selection; why: plan choice survives authentication and only an explicit confirmed purchase returns to Rituals.
- Billing is Apple IAP via RevenueCat (@revenuecat/purchases-capacitor) in src/lib/billing.ts, native-only; web keeps the placeholder trial. The revenuecat-webhook edge function (shared-secret auth) is the authoritative sync of entitlements.premium — clients never update that column directly; why: prevents client-side privilege escalation.
- Purchase flow rules live in purchaseFlow.ts; match only the selected store package and never auto-start trials at sign-in or use web preview access on native; why: Apple confirmation must precede native trial access.
- Native release configuration must load bundled dist with no server.url; why: App Store launch must not depend on a development preview website.
- App launch uses Sonner with the existing theme store and no shell-worker registration; keep the legacy worker cleanup scoped to app caches, because stale chunks can cause blank launches.
- Pin the Capacitor family together and use a RevenueCat plugin whose declared peer range supports that major; keep npm and Bun locks synchronized, because incompatible plugin updates prevent native dependency installation.
- Native social sign-in (Google/Apple) hands off through the hosted bridge: the native WebView opens https://burnandshed.com/auth/native?provider=..., OAuth completes on the hosted origin, and /auth/native-bridge returns tokens via the app-origin URL hash; the managed /~oauth routes are not served inside the bundled native app, which is why direct lovable.auth OAuth showed a 404.
